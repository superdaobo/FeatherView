# FeatherView v0.1.1 手动验收清单

> 使用发布构建的 `FeatherView_0.1.1_x64-setup.exe` 安装后进行。

## 一、文件关联

准备文件（放入同一目录，路径含中文/空格）：

```text
普通文档.md
带 空 格 的文档.md
测试.多个.点.markdown
中文日志.log
settings.json
config.yaml
```

| # | 场景 | 预期 | 结果 |
| --- | --- | --- | --- |
| 1 | 应用未运行时双击 `普通文档.md` | 应用启动并直接进入阅读页 | ☐ |
| 2 | 应用已运行时双击 `带 空 格 的文档.md` | 现有窗口恢复聚焦并打开该文件，无第二个实例 | ☐ |
| 3 | 右键 `settings.json` → 打开方式 → FeatherView | 正确打开 | ☐ |
| 4 | 打开 `中文日志.log` | 内容正确（无乱码），窗口标题为「中文日志.log — FeatherView」 | ☐ |
| 5 | 最近文件列表 | 以上文件均出现在最近列表，无重复项 | ☐ |
| 6 | 双击一个不支持的扩展名文件（如 `.xyz`） | 显示 Unsupported 提示，不崩溃 | ☐ |
| 7 | 在「设置 → 应用 → 默认应用」或资源管理器中移除关联 | 打开方式列表不再包含 FeatherView | ☐ |
| 8 | 卸载 FeatherView | 关联的打开命令被清理 | ☐ |

## 二、单实例

| # | 场景 | 预期 | 结果 |
| --- | --- | --- | --- |
| 1 | 启动应用后最小化窗口，双击关联文件 | 窗口恢复并聚焦，打开文件 | ☐ |
| 2 | 快速连续双击两个不同文件 | 只打开第一个，提示「一次只能打开一个文件」，无崩溃 | ☐ |
| 3 | 双击与当前已打开相同的文件 | 重新读取该文件（内容刷新），最近记录不重复 | ☐ |
| 4 | 任务管理器检查 | 始终只有一个 featherview 进程长期存在 | ☐ |

## 三、阅读位置

对 Markdown、TXT、代码（如 `.rs`）和 JSON 分别执行：

| # | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- |
| 1 | 打开长文档，滚动到约 50%，关闭应用 | 重新打开（最近文件）回到接近 50% 的位置，显示一次「已恢复上次阅读位置」 | ☐ |
| 2 | 首次打开一个从未读过的文件 | 从顶部开始，无恢复提示 | ☐ |
| 3 | 恢复后调整字号（Ctrl++ / Ctrl+-）再重新打开 | 位置大致保持（比例恢复） | ☐ |
| 4 | 修改窗口大小后重新打开 | 位置不跳顶不跳底 | ☐ |
| 5 | 修改文件内容（变短/变长）后重新打开 | 不崩溃，位置在有效范围内 | ☐ |
| 6 | 设置中关闭「记住阅读位置」 | 不再保存/恢复；再开启后可恢复旧记录 | ☐ |
| 7 | 设置中「清除阅读位置记录」（确认） | 所有位置清除，最近文件与主题字号保留，显示成功 Toast | ☐ |
| 8 | Markdown 带标题长文滚动后重开 | 优先定位到视口顶部附近的标题 | ☐ |
