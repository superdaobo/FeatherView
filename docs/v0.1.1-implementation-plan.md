# FeatherView v0.1.1 实施计划

> 版本定位：Windows 实用性与可靠性更新（文件关联、单实例、阅读位置记忆、交互优化）。
> 基线：v0.1.0（已发布，GitHub Actions 全绿）。

## 一、当前架构分析

- **渲染器注册表**（`src/renderers/registry.ts`）：RendererDefinition 分发，本轮不改。
- **平台抽象**（`src/services/platformService.ts`）：文件选择/拖拽/`startup_args` 集中于此；本轮扩展启动参数规范化与外部打开监听。
- **文件打开入口**：所有入口汇聚 `documentStore.open()`；本轮新增冷启动参数、第二实例参数两个入口，同样汇聚。
- **Rust**：`read_file`/`file_exists`/`file_metadata` 命令与 `AppError { title, message, code }` 不动；新增 single-instance 插件注册与窗口恢复回调。
- **设置**：`ReaderSettings` 在 `src/services/settingsService.ts` 持久化；本轮增加 `rememberReadingPosition`。
- **CI**：`.github/workflows/build.yml` + `release.yml` 无需改动（文件关联来自 tauri.conf.json 配置）。

## 三、方案设计

### 3.1 Windows 文件关联（阶段 B）

- 使用 Tauri 2 `bundle.windows.fileAssociations`（当前 CLI schema 确认支持 `ext/name/description`），NSIS 安装器在安装时写入 `HKCU\Software\Classes`，卸载自动清理，不覆盖用户默认程序（仅提供"打开方式"）。
- 关联范围：`md/markdown/mdown`、`txt/log`、`json`、`yaml/yml`、`toml`。不关联图片/代码/系统文件（避免抢占编辑器）。
- 不写自定义注册表脚本。

### 3.2 冷启动参数（阶段 A）

- 前端纯函数 `parseLaunchArgs(args, exists)`：
  1. 丢弃首个参数（exe 自身）与 `-`/`/` 开头 Flag；
  2. 去除首尾引号（防御）；
  3. 逐个 `file_exists` 校验（排除不存在路径/文件夹/URL）；
  4. 多个有效文件只取第一个，返回 `{ source?, extraCount }`。
- `resolveInitialDocument()` 复用该函数，异常静默（不崩溃）。

### 3.3 单实例（阶段 C）

- `tauri-plugin-single-instance@2.4.3`（官方插件，MIT/Apache-2.0，体积 ~0.1MB）。
- Rust 回调：`show + unminimize + set_focus` 主窗口 → `app.emit("external-file-open", args)`。
- 前端 `useExternalFileOpen`（App.vue 挂载，onUnmounted 清理）：
  - 冷启动：`resolveInitialDocument()`；
  - 事件：监听 `external-file-open`；
  - 防重：模块级处理锁 + 相同 identity 短时间内忽略；
  - 多文件只取第一个 + 单次 Toast。
- 开发模式注意：single-instance 在 dev 同样生效，热更新重复注册由卸载清理解决。

### 3.4 阅读位置（阶段 D/E）

- `ReadingPositionRecord { sourceId(path 规范化), path, rendererId, scrollTop, scrollRatio, viewportHeight, contentHeight, headingId?, updatedAt }`。
- `getDocumentIdentity`：路径统一 `\` 分隔、去尾部空白分隔符、小写化（Windows 大小写不敏感；UNC 前缀保留）。
- 存储：localStorage `featherview.readingPositions.v1`，上限 150 条按 `updatedAt` 淘汰，损坏 JSON/NaN/负数/缺失字段全部过滤。
- 保存时机：滚动防抖 500ms；打开新文件前（watch source）；离开阅读页（onBeforeUnmount）；窗口关闭（pagehide）。
- 恢复时机：渲染完成 → nextTick + rAF + ResizeObserver，最多 5 次重试；策略 headingId → scrollRatio → scrollTop（高度一致时）→ 顶部；`clamp(0, scrollHeight - clientHeight)`。
- 设置：`rememberReadingPosition` 默认 true；关闭不删数据；设置页提供“清除阅读位置记录”（确认 + Toast）。
- 恢复成功 Toast“已恢复上次阅读位置”一次。

### 3.5 交互优化（阶段 F）

- 窗口标题：`windowService.setTitle()`（capability `core:window:allow-set-title`）；首页 `FeatherView / 轻阅`，打开文件后 `文件名 — FeatherView`。
- 拖拽文案：“松开以使用 FeatherView 打开”；拖入文件夹 → file_metadata 校验 → Toast“暂不支持打开文件夹”。
- 打开加载：`documentStore.open` 加载中忽略重复调用；按钮禁用。
- 重复打开当前文件：允许重读（最近记录按 path 去重不重复）；重读前保存位置、完成后恢复。

## 四、测试方案

- **Vitest**：launchArgs（正常/中文/空格/引号/不存在/文件夹/多参数/Flag/空/不支持扩展名）、readingPositionService（存取/更新/删除/清空/损坏 JSON/上限淘汰/非法值过滤/路径归一/关闭不保存/边界 clamp）、ReaderPage 交互（恢复/首次不恢复/切换前保存/关闭不恢复/清除后顶部/加载防重复/窗口标题/Toast 一次）。
- **Rust**：现有 14 个测试保持通过；新增参数解析在 TS 侧，Rust 无需新增（若 launch 模块落 Rust 则补测试——当前方案为 TS）。
- **E2E（WebView2 CDP 冒烟）**：构建后启动验证首页/打开/标题；单实例与文件关联标注“构建通过，待 Windows 实机安装验证”。

## 五、风险与回滚

| 风险 | 缓解 |
| --- | --- |
| single-instance 在 dev 影响多实例调试 | 文档说明；插件仅在主进程注册，不影响 `tauri dev` 正常使用 |
| 文件关联构建后本机未实机安装验证 | README/QA 文档明确标注“待实机验证”；提供手动验证步骤 |
| 位置恢复导致跳转抖动 | 有限重试 + clamp + 高度一致性判断；恢复失败回退顶部不崩溃 |
| localStorage 版本迁移 | 独立 key `readingPositions.v1`，损坏即回退空 |
| 版本升级遗漏 | 统一改 package.json / Cargo.toml / tauri.conf.json / Cargo.lock |

**回滚**：所有改动集中在独立分支 `feat/v0.1.1`，单实例插件可整体移除（lib.rs 一行 + Cargo.toml 一行）；文件关联为配置项可回退；阅读位置为前端服务可删除。
